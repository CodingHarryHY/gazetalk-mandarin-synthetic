# ADR-0008: Config-file credentials with runtime-only handling

- Status: accepted
- Proposed and accepted date: 2026-09-29, Europe/Copenhagen
- Author: Codex implementation assistant
- Requester: project owner, explicitly requested API key configuration in a file for a local proxy
- Affected version: 0.1.2
- Supersedes: the environment-only authentication decision in ADR-0007
- Related decision: ADR-0004 (immutable experiment evidence)

## Context and decision

The owner wants to configure the proxy address and its key in the same TOML file.
Support optional generation.api_key. Strip surrounding whitespace; a nonempty
configured value overrides OPENAI_API_KEY, otherwise use the environment. Keep
the missing_api_key failure if neither source provides a nonempty credential.
No .env loader or additional authentication protocol is introduced.

## Rationale and alternatives

Requiring environment-only setup would conflict with the requested local workflow.
Copying the key into experiment snapshots would needlessly duplicate authentication
material and make credential rotation invalidate resume. Instead, extract the
validated key into a Config field excluded from repr and equality. Keep config.values
credential-free, and pass the runtime field only to the SDK constructor.

## Consequences and evidence boundaries

The original TOML file retains the plaintext key; this change does not encrypt it.
Generated snapshots, fingerprints, prompts, cache requests, and attempt request
bodies do not include the configuration key. TOML/schema failures report generic
errors without input values. Rotating only the key preserves the same-version run
fingerprint; changing the endpoint, code, or generation settings still requires
a new run directory. Upgrade defaults use fresh v0.1.2 directories.

The existing local pilot endpoint was preserved. No live proxy call was made.
Tests verify the actual config-to-client path using a mocked SDK and check all
generated run files for the test credential. See ../versions/0.1.2.md.
