# ADR-0010: Schema-ordered persona JSONL display

- Status: accepted
- Date: 2026-10-02, Europe/Copenhagen
- Author: Codex implementation assistant
- Requester: project owner
- Affected version: 0.1.4
- Supersedes: none; narrows the persona serialization choice in ADR-0004

## Context and decision

Canonical JSONL serialization alphabetized persona fields, making the output
harder to inspect against `persona.schema.json`. Preserve the existing canonical
sorting for hashes and all other JSONL files. For `personas.jsonl` only, order
top-level and `behaviour_profile` fields by their schema `properties` and write
without key sorting. Persona values, IDs, planning, and validation are unchanged.

## Alternatives considered

Changing canonical serialization globally would alter every JSONL file and
integrity hash. Reordering old run files would modify archived evidence. Both
exceed the requested display change.

## Consequences and validation

The package source changes, so a fresh run directory is required by the
existing snapshot fingerprint rule. A test compares written key order with
both schema property lists and verifies that other JSONL sorting and run
integrity still work. The previous pilot run is preserved.
