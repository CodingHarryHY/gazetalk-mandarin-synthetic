# ADR-0004: Independent validation and immutable run evidence

- Status: accepted
- Proposed date: 2026-09-29, Europe/Copenhagen
- Accepted date: 2026-09-29, Europe/Copenhagen; exact approval time not recorded
- Author: Codex implementation assistant
- Design approver: project owner, in this conversation
- Affected version: 0.1.0
- Supersedes: none
- Sources: USER-2026-09-29 and the source register in ../sources.md

## Context
The old independent validator missed top-level extra fields and resume trusted IDs
without checking stored content or changed generation conditions.

## Decision
Use formal local JSON Schema plus order/nonblank checks, exact request cache keys,
validated attempt receipts, input hashes, code/prompt/config snapshots, and a run
lock. Only validated records enter output. Resume rejects drift and damaged files.
Use bounded whole-dialogue retries with validation feedback. Preserve each attempt
and reported usage; do not log SDK exception text or secrets.

## Alternatives considered
Silently skipping bad records or repairing JSON by adding delimiters hides failure.
Reusing old IDs with new prompts mixes experimental conditions. SDK retries plus
application retries obscure attempt counts, so SDK retries are disabled.

## Consequences, evidence limits, and reconsideration
Manual recovery is required for a damaged JSONL tail. Hashes are integrity checks,
not cryptographic signatures or exact model-output reproducibility. macOS/Linux
locking is supported; Windows is outside v0.1. Tests exercise failures and resume.
A changed fingerprint requires a new run directory.

## Validation and implementation references
See ../../README.md, ../design.md, ../versions/0.1.0.md, and the offline tests
in tests/test_pipeline.py. Actual execution timestamps, requests, and hashes
belong to the corresponding run manifest and attempt log.
