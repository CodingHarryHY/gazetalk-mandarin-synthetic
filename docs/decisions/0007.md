# ADR-0007: Explicit configurable API base URL

- Status: accepted
- Proposed and accepted date: 2026-09-29, Europe/Copenhagen
- Author: Codex implementation assistant
- Requester: project owner, explicitly requested a configurable OpenAI API address
- Affected version: 0.1.1
- Supersedes: the hard-coded endpoint implementation in 0.1.0
- Related decision: ADR-0004 (immutable run evidence)

## Context and decision

The client previously forced https://api.openai.com/v1. Add generation.base_url
to TOML, defaulting to the same official address when omitted. Validate an
HTTP(S) base URL, normalize trailing slashes, reject endpoint suffixes and embedded
credentials/query/fragment, and pass the result explicitly to OpenAI(base_url=...).
Keep authentication in OPENAI_API_KEY. Store the effective address in the immutable
config snapshot, so changing providers requires a new run directory.

## Rationale and alternatives

An explicit TOML setting makes the destination reviewable with other experiment
settings. An ambient OPENAI_BASE_URL override could silently change the destination
without changing the saved conditions, so it is not used. Secrets in URLs could
be copied into snapshots; reject them and retain environment-based authentication.
No protocol adapter is added: the existing Responses and strict-schema contract
remains unchanged. A provider's claim of OpenAI compatibility is not sufficient
evidence that all required request options are supported.

## Evidence and consequences

The installed SDK exposes base_url. The official OpenAI
[compatible endpoint example](https://developers.openai.com/cookbook/examples/partners/aws/openai_models_with_amazon_bedrock)
also demonstrates configuring an API base and addressing /responses beneath it.
This supports the SDK mechanism, not compatibility of an arbitrary gateway.

Default configs use fresh v0.1.1 run directories. Old bundles are retained. The
URL belongs to the run snapshot rather than the per-dialogue outer record, keeping
the established JSONL record format unchanged. Model permissions and live endpoint
behavior remain unverified. See ../versions/0.1.1.md for actual validation evidence.
