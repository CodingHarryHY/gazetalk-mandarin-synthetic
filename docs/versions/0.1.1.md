## Change and rationale

See ADR-0007. generation.base_url is configurable, defaults to the official
endpoint, is validated/normalized, and is passed to the SDK. Its effective value
is included in the immutable run snapshot and fingerprint. OPENAI_API_KEY remains
the authentication source. No environment URL override or protocol fallback is added.

Package and lockfile project versions are 0.1.1. Default configs now select
pilot_v0_1_1 and batch_2000_v0_1_1. Historical run directories and the 0.1.0 archive
were not modified. No new persistent run bundle was prepared during this change.

## Validation

Command from the repository root:

~~~bash
PYTHONPATH=mandarin/src mandarin/.venv/bin/python -B -m unittest discover -s mandarin/tests -v
~~~

Result: 30 tests passed in 0.870 seconds, exit code 0. The three added tests cover:

- Missing setting uses the official default; custom local path/port and trailing slash normalize correctly.
- Malformed addresses, embedded credentials, queries/fragments, and full endpoint paths are rejected.
- Custom address reaches the mocked SDK through the real pipeline and is recorded in the snapshot;
  a conflicting ambient URL is ignored and changing the configured address blocks resume.

The existing adapter test also checks the default SDK address. Targeted IDE
inspection of config.py, clients.py, generate.py, and test_pipeline.py reported
no warnings. Test clients were mocked and run bundles were temporary.

## Remaining limits

No actual custom address was supplied and no live network generation was run.
The service must support Responses, strict JSON Schema, and the configured model
and request options. Clinical evaluation and external CHAT verification remain
pending as documented in 0.1.0; this change does not resolve those gates.
